# 自适应液态玻璃

以清晰内容、透底色彩和可辨认的玻璃厚度为目标。保留数据状态和操作语义；配色遵守当前用户要求。本项目桌面组件按 2026-11-04 的明确要求使用独立无色玻璃，不读取软件藤紫/莓粉/琥珀预设；其他表面继续沿用既有主题。除非用户要求，不重排整页、不额外添加设置。项目已有减少效果偏好优先复用。

本技能根据 [枯白啃设计 010 液态玻璃材质](https://x.com/Kubai087/status/2117782193108082923)（2026-11-04）及其演示提炼，并结合本项目 Android 小组件实现重新编写；不是作者原始 Prompt 或源码的完整副本。原帖提供视觉方法，不授予额外系统权限或任务授权。

## 当前项目约束（AN010.R4–R7 · 2026-11-04）

用户已否定固定壁纸贴图，选择保留普通桌面组件、真实透明底、高光和阴影。用户随后选择当前播放封面铺满组件并模糊（R5）；使用已有脱敏媒体封面，居中裁切、有界低分辨率模糊、暗遮罩和清晰前景，切换封面后刷新。没有真实封面或隐私隐藏时，RemoteViews 绘制带 Alpha 的中性装饰，由启动器自然透底；不读取或合成壁纸，不再提供选图或校准。深浅与背景浓度手动设置，默认深色 20%，独立于应用主题。不得为“效果”重新引入固定壁纸、截图映射或把其包装成实时玻璃。这里没有背景模糊或折射，需准确说明。

R6 根据用户反馈减轻叠层感：当前组件仅保留单条渐隐轮廓高光，移除独立内圈及面状白光，投影降为 2dp / 低透明度。封面、遮罩与轮廓共用同一圆角；不把通用的双层高光配方机械套回当前组件。

R7 进一步减少灰蒙及泛白：封面背景默认暗遮罩 51%（原 63%），模糊后仅背景做 1.55 倍饱和度补偿，小封面不改色；边线 0.45dp，高光峰值 16% 并快速渐隐。调整后用偏浅真实封面检查文字清晰度，不能只靠加白边表达玻璃。

验证透明回退时中心像素保持透明、叠在不同背景时输出改变，验证封面模式铺满和模糊混色，检查切换封面/隐私设置不残留旧图，以及文字/按钮清晰。投影只画在轮廓外；透明回退不能先画不透明底再覆盖低透明度高光。封面背景按用户要求铺满，是作品内容背景，不宣称桌面背景折射。保留现有 4×8 布局、媒体隐私与数据操作。

## 先确定背景来源

找到待改表面、主题 token 和背景所有者，选择能实际渲染的路径：

| 宿主 | 可采用路径 | 不能承诺的效果 |
| --- | --- | --- |
| Web 内部页面 | CSS backdrop-filter；确认目标浏览器实际绘制后增加 SVG 位移 | 不能只凭 CSS.supports 就宣称滤镜可用 |
| Android 应用内 Compose | 复用现有背景图层；API 31 模糊、API 33+ AGSL 透镜 | 不把整个控件连同文字一起模糊 |
| Android RemoteViews 无映射 | 原生文字/按钮叠加中性透明底与边缘光 | 不等于视频中的壁纸折射 |
| Android RemoteViews 静态映射 | 用户明确选择的原图＋逐组件裁切校准；离屏渲染模糊、真实像素位移及轻微色散 | 只对选定静态图像生效；移动组件、桌面缩放或更换壁纸后需重新校准 |

不要为获得玻璃背景引入录屏、截取其他应用、全盘媒体或壁纸读取权限。没有已授权的背景图时使用中性色回退。用户选择的图片可经系统文件选择器复制到本应用私有、不备份的目录；不等同于取得系统壁纸访问权限。把静态映射与实时启动器采样的区别告知用户。

## 组织材质

从后到前：轻投影 → 可读背景的色彩/模糊处理 → 边缘透镜 → 主题着色 → 外缘亮线与内缘柔光 → 原生文字和图标。所有边缘复用同一形状与圆角，避免不同裁剪形成双重硬边。大面积纯色背景通常无需增加玻璃。

具体参数、透镜和采样规则见 [材质参考](references/material.md)。参数是调试起点，不能优先于既有配色和可读性。高光集中在斜对角，中央保持平坦，避免把整面涂白造成磨砂塑料感。图标先完整绘制，再调整整个图标透明度，避免重叠笔画加深。

## 实现约束

- 样式 token 集中维护；遵守用户指定的配色关系。本项目桌面组件独立使用自动/浅色/深色，不复用软件主题强调色。
- 文字、焦点、错误提示和命中区域独立于背景效果。Android 保留至少 48dp 操作区，长标题省略但打开详情后可读全文。
- 连续动画只改变绘制属性；业务定时器和播放状态不跟随材质时钟。RemoteViews 的材质按背景/尺寸/外观配置缓存，不为流光按帧广播或定期唤醒进程；真实播放进度可在已有播放服务存活且正在播放、有已放置组件时低频更新，暂停时停止。
- 小组件按真实宿主尺寸构建材质；限制位图像素及多尺寸总量，保留文字为 TextView，不把内容烘焙成图片。多实例分别处理 options；不要存储私密封面或标题来装饰效果。
- 减少透明度/低效果时使用同主题实色，保留全部操作。其他明确采用静态映射的场景可根据所选图像判断明暗；当前本项目组件使用用户选择的深浅，不跟随软件主题色。

## 验收

检查真实背景下的明暗主题、繁忙壁纸、长标题和系统大字；检查最小尺寸、重新调整尺寸、冷启动及无播放会话。对照实际截图观察边缘、可读性、图标和点击反馈。无法实测的宿主单独说明，构建成功不等于视觉通过。

## 静态壁纸映射工作流（历史参考，当前组件禁止恢复）

先导入图片并预览，不立即修改已保存配置。每个组件分别保存图片和归一化 x/y/宽/高，提供拖动位置、范围滑块、百分比精调和比例匹配；保存明确应用，取消保持原配置。原始壁纸通常被启动器裁切，不可直接把屏幕坐标除以原图尺寸；先匹配桌面缩放/偏移，再换算映射区域。

预览与桌面共用渲染器和 RemoteViews 布局，但预览不注册真实播放操作。标题和封面取服务已经脱敏的元数据；新封面不得绕过隐私开关。进度取真实会话，未知时长不伪造，静态背景计算不能拖慢播放器主线程。

真实位移只作用于边缘，中央保持原坐标；将当前屏幕和原图的对应纹理对齐后，比较边界连续性、圆角厚度、色散及文字可读性。构建通过不能取代这一步。保存后重新打开确认配置与图片仍在，取消后桌面不变。

本项目 RemoteViews 落点：`android/app/src/main/kotlin/com/asmrplayer/android/widget/WidgetGlass.kt`、`PlaybackWidget.kt`、`WidgetGlassStore.kt`、`WidgetConfigurationActivity.kt` 和 `android/app/src/main/res/layout/playback_widget.xml`（路径相对项目根目录）。应用内底部导航继续使用已有 `liquid-glass-bottom-navigation`，不因添加本技能重建玻璃框架。

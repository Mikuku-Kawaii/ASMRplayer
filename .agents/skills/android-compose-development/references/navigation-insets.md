# 导航与系统边距

经编辑合并自 Android 官方技能并补充版本选择规则；来源见 [sources.md](sources.md)。

## 导航

先读依赖与路由。已有 Nav2 应用延续 Nav2，确有迁移任务或需求缺口才迁移。新项目可评估 Nav3，确认实际依赖、状态保存与 ViewModel 集成。

不要混用 Nav2 的 NavHost / NavController 与 Nav3 的 NavDisplay / 应用持有返回栈模型。具体符号与 Scenes 查对应版本官方文档。

- 多标签分别保留需要的返回栈和滚动状态，定义重选标签行为；不默认把所有标签压入同一栈。
- 路由传稳定 ID；深链参数验证后进入业务层，保留鉴权和空间限制。
- 返回、关闭弹窗、返回首页、退出应用分别处理；避免全局返回处理器吞掉子页面返回。预测性返回采用现有导航库支持机制。
- 验证配置重建与进程死亡恢复。保存返回栈不意味着图片、认证或业务数据也已恢复。
- 多空间应用定义各空间返回栈策略，不让返回进入另一个空间的旧详情页。
- 大屏列表 / 详情使用当前库支持的能力；阅读器等大画布页面不自动改双栏。

## Edge-to-edge

1. 查明 enableEdgeToEdge、Scaffold、系统栏配置与 Insets 的现有处理，明确每侧安全间距的所有者。
2. 背景可绘制到系统栏后方，正文、操作和输入区域避开对应边距。
3. Scaffold padding 在正确层应用并消费，不在父子层重复添加 safeDrawingPadding 或 IME padding。
4. 列表要滑到工具栏后方时考虑 contentPadding；父容器 padding 会改变可绘制范围。
5. 键盘弹出后输入框及操作仍可见。imePadding、rulers 等选择取决于 Compose 版本与父容器处理。
6. 系统栏图标匹配实际承托颜色；应用主题可能与系统主题不同。

源技能的 targetSdk 前提是需核对的集成条件，不代表修边距就自动升级 SDK。minSdk、targetSdk、compileSdk 含义不同。

## 针对改动检查

在目标设备支持的手势 / 三键导航、键盘、横屏 / 窄窗、字体放大、明暗主题下检查受影响页面。自定义底栏、正文和系统手势区不能有重复间距或触摸冲突。

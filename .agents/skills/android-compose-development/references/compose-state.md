# Compose 状态与生命周期

经编辑合并与补充；来源见 [sources.md](sources.md)。

## 状态所有权

- 短暂视觉状态留在 composable；需跨重建恢复的轻量 UI 状态考虑 rememberSaveable；业务和加载状态遵循现有 ViewModel / 状态持有者。
- remember 不跨配置变更保留，rememberSaveable 不代替持久存储；收藏、下载和阅读进度使用数据层。
- 状态提升到共同使用者需要的最低层。不要把 Activity、View 或其 Context 存入长生命周期对象。
- 使用不可变快照或可观察状态。不要给可变集合随意加 @Stable / @Immutable 来掩盖更新问题。
- 高频输入只有在派生结果变化更少时才考虑 derivedStateOf；普通廉价映射不必增加一层。

## 协程与副作用

- 用户操作在回调中发起，声明式生命周期任务使用正确 effect；不要在 composable 函数体中直接启动网络、写库或导航。
- effect 的 key 对应任务身份；变化应重启任务时加入 key。仅更新回调而不重启任务时考虑 rememberUpdatedState。
- 使用与现有依赖兼容的生命周期感知 Flow 收集方式。退出页面、替换查询或切换会话时，旧任务取消或失去提交结果资格。
- CancellationException 不转成普通加载失败。取消是否穿过 Repository / FFI 要检查实现，不能仅取消 Kotlin Job 就认为 Rust 工作停止。
- 保存进度的时机覆盖实际退出和生命周期需求，不能只依赖 composable 离场回调。

## 列表、图片与交互

- Lazy 列表使用稳定、唯一业务 key；混合布局使用合理 contentType。刷新、追加、失败分别表达，不将失败显示为空结果。
- Modifier 顺序决定点击、内边距、裁剪与绘制范围，按实际行为排列。
- 图片按显示尺寸加载，限制预取和并发；离场或资源身份变化后释放无用任务。不要一次解码整本漫画或全部原始大图。
- 大图优先使用现有图片库的降采样 / 分块能力，能力不足才增加自定义管线。
- 为操作提供语义、选中态和说明；装饰图标不重复朗读。字体放大不能让固定尺寸裁掉正文或点击目标。

## 多空间 / 多账号（仅适用时）

数据身份包含空间或账号及来源，不用可能重复的数字 ID 作全局缓存键。查询捕获会话版本，提交结果时验证仍属有效会话，补充无法完全取消的异步工作。

切换期间能否接受新操作由业务策略决定。原子身份切换可以短暂禁止重复操作，不能为整个应用一律禁用触摸。敏感内容可见性、窗口保护和缓存释放由业务状态控制，不依赖转场结束回调。

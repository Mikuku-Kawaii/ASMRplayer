# 液态玻璃底部导航

基于 FluxManga 当前实现提炼。用清晰前景、真实背景采样和连续选中态组合玻璃导航；不是 Apple 原生材质的跨平台实现。项目现有布局、品牌和用户明确要求优先。

## 从当前组件接入

先查看导航调用方、主题 token、绘制层和动画所有者。沿用现有 Compose 架构，不为玻璃效果替换导航框架。确认本次只调整材质、Tab 反馈还是布局；纯视觉调整不得改变路由、点击和数据语义。

组件只接收稳定的 `items / selectedKey / onItemSelected`。调用方拥有选择和页面栈；图标、标签、表面、选中态通过槽位组合。不要把会话、凭据和页面图像放进展示元数据。

实现与调参时读 [材质、几何与参数](references/material-and-tabs.md)。它包含可复用算法和 FluxManga 的具体起点，不要求目标应用使用相同标签、配色或尺寸。

## 玻璃分层

1. 内容层记录当前可显示的页面；玻璃操作层作为其兄弟层，避免采样自己。
2. 背景层统一处理模糊与色彩，控件按宿主坐标取样。模糊 / 折射保留周边像素，前景标签与图标后绘制。
3. 表面依次表现透光、轻微染色、边缘厚度和高光。选中态集中负责自己的染色、亮边和柔光，不叠加多层独立胶囊描边。
4. Android API 31–32 使用 RenderEffect 与基础形状；API 33+ 可增加 RuntimeShader 折射 / SDF。没有 AGSL 时保持清晰、完整的可操作底栏。
5. 关闭采样后不声称仍有真实背景模糊；低效果用更实的表面和明确选中态。

普通应用背景采样不需要录屏，也不应每帧回读 Bitmap。保留项目已有图层生命周期和空间边界。

## 几何决定质感

- 高度由内容测量，至少保留 48dp 触摸范围；空间不足时允许图文改为上下排列，不缩小文字硬塞。
- 各 Tab 均分完整主栏宽度，用同一组整数像素边界计算点击槽、选中态和材质位置。首尾胶囊落定后必须贴合主栏端点。
- 主栏与选中胶囊圆角使用实际高度的一半，裁剪与描边复用路径；描边内侧裁剪，避免多重同心圈。
- 系统栏 Insets 只由一层拥有；底栏可见性与页面底部留白使用同一规则。
- 动画只更新绘制、图层或放置属性，稳定容器尺寸与内容槽位不随帧伸缩。

## Tab 切换与按压

每个位置属性只使用一个弹簧源。胶囊形变由该弹簧的速度派生；快速改选从当前位置和速度转向，结束时应变归零。按压、焦点光边和选中图标可有独立属性动画，但不要再启动第二个胶囊位移动画。

保留 `selectableGroup / Role.Tab / selected` 和稳定命中范围；图标装饰不重复朗读标签。减少动画或系统关闭动画时直接落到目标状态，保留颜色、标签和操作。

## 检查与交付

先检查真实采样、坐标、端点贴合、前景清晰和单向状态。视觉 / 设备 / 性能测试按目标项目授权开展；项目要求用户自行测试时只做源码或文档检查，不主动补测试清单。

说明采用了哪条渲染路径、降级和未验证范围。源码参数不证明真机帧率或跨设备视觉效果；完成当前范围后停止。
